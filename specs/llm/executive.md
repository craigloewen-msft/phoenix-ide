# LLM Provider - Executive Summary

## Requirements Summary

The LLM provider abstracts communication with multiple LLM APIs behind a common interface. Users select their preferred model while the system handles provider-specific translation internally. Phoenix supports built-in Anthropic/OpenAI models, an availability-gated local Ollama GPT-OSS route, plus `PHOENIX_LLM_MODELS` entries that declare a backend (`anthropic`, `openai_responses`, or `openai_chat_completions`), optional wire model name, user-facing family, and output cap. External entries are additive by default; `PHOENIX_LLM_MODELS_ONLY=1` makes the external specification catalog authoritative and excludes built-in definitions without suppressing independently discovered local routes. Base URL overrides are exact endpoints, not gateway roots; Phoenix does not append hidden provider path suffixes. With credential-helper auth and base URL overrides, Phoenix can opportunistically query derived `/v1/models` endpoints to filter the configured model set; if listing is unavailable, Phoenix falls back to configured models. Authenticated cloud routes register only models with configured API keys or a credential helper; the local Ollama route instead requires successful unauthenticated model discovery plus a confirmed GPU-offload and context-length capability probe. Requests use a common format (system prompt, messages, tools) that gets translated per backend. Model specs also classify reasoning-effort capability as known-native, unknown, or unsupported; explicit per-conversation overrides persist independently from provider-native defaults and are translated only when explicitly selected. Responses are normalized to text blocks, tool use requests, end-of-turn indicators, and usage statistics. Errors are classified into exhaustive named categories plus explicit policies for automatic runtime retry and user-triggered resume. Network failures, transient rate-limit throttles, server errors, and timeouts are auto-retryable; auth failures are not auto-retryable but are user-resumable after credentials are refreshed. Quota exhaustion remains non-auto-retryable but user-resumable after its reset window; context exhaustion remains a non-resumable terminal path. Request observability includes provider-centric TTFT measured from request transmission or dispatch to the first generation-bearing provider event, excluding acknowledgements, pings, metadata-only events, usage-only events, and terminal events. TTFT remains content-free and privacy-preserving, and aggregate analysis keeps provider, model, and transport as first-class dimensions. When traffic routes through the codex backend, Phoenix uses only its native Codex login credential. Authoritative account usage supplies current, weekly, additional-family, credit, and spend-control quota state; 429 responses carrying structured quota state are parsed into a plan-aware terminal error rather than an opaque retryable message.

## Technical Summary

The ChatGPT/Codex-auth backend supports automatic prompt caching with a stable `prompt_cache_key` but rejects GPT-5.6 direct-platform `prompt_cache_options` and explicit breakpoints. A pinned upstream codex-rs and sanitized live-wire investigation is recorded in [`codex-prompt-caching-investigation.md`](../../docs/research/codex-prompt-caching-investigation.md). Confirmed parity work is tracked separately for Responses Lite request shaping, WebSocket continuation, account-specific model discovery, and stable system-prompt snapshots.

Implements `LlmService` trait with `complete()` method returning `LlmResponse`. Backend implementations translate the common request format to Anthropic Messages, OpenAI Responses, or OpenAI Chat Completions JSON and normalize responses back. Ollama reuses the Chat Completions wire translator through a distinct exact endpoint and typed unauthenticated service route. `OllamaWireModel` distinguishes an operator pin from automatic selection: a pin is honored exactly, while automatic selection accepts only GPU-forced aliases. A bounded startup `/v1/models` probe finds the tag, and a second bounded unauthenticated `/api/show` probe confirms its persisted `num_gpu` forces full offload and reads the `num_ctx` it serves, clamped to the architecture ceiling and carried into `ModelSpec::context_window` rather than assumed. Any unmet condition leaves `ollama/gpt-oss:120b` unregistered, without applying cloud discovery fallback and without substituting a default context window. Chat Completions streaming requests include usage, preserve tool-call IDs, classify inline errors, reject unterminated streams, and omit private reasoning from normalized visible output. Base URL overrides are exact endpoints; Phoenix does not construct gateway paths. `ModelRegistry` merges built-in specs with configured specs unless external-only catalog mode is selected, registers only models with an available auth route, independently adds availability-gated local routes, and keeps Codex bridge routing scoped to built-in OpenAI Responses models. `LlmError` includes exhaustive `LlmErrorKind` enum (no `Unknown` variant, no catch-all) with separate `auto_retry_policy()` and `user_resume_policy()` methods. `LoggingService` records content-free request correlation, model/provider/transport, duration, retry attempt, classified failures, and token/cache counts on bounded request spans. REQ-LLM-008 now normatively defines provider-centric TTFT from the transport dispatch boundary to the first generation-bearing provider event and requires provider/model/transport aggregates without storing reconstructable provider payloads. The OpenTelemetry layer exports only designated Phoenix spans and no tracing events; local logs retain an independent `EnvFilter`. Streaming diagnostics retain counts and types rather than provider payload, frame, prompt, tool-schema, argument, header, or parser-buffer content. Usage tracking includes input/output tokens and cache statistics for context window computation.
